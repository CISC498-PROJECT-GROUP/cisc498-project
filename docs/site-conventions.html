Site conventions

Required reading before any work in web/ — the student's site: Canvas, Stellic and WebReg in one place, with the assistant beside them. The site holds no UD session of its own; everything it shows comes through the backend, made with the signed-in student's own UD session.

Preact + hooks · TypeScript strict · bundled by Bun.build · hash routes · one origin with the API

01

Reaching UD

  • Every UD request goes through services/api/upstream.ts: a client builds the real URL it would call from a browser on that system (https://udel.instructure.com/api/v1/…) and upstreamFetch sends it to the backend's /api/up/<host>/<path>. The backend adds the student's cookies, CSRF tokens and Origin headers, and follows redirects. Never fetch a UD host directly, and never try to hold a UD cookie in the page.
  • Our own routes (sign-in, chat, study PDFs) go through services/api/backend.ts (callBackend). Writes carry X-Requested-With: canvas-assistant — both helpers add it.
  • A 401 from either means the student's UD session is gone: onSignedOut fires and the app returns to the sign-in screen. Signing out reloads the page, so no student's memoised data outlives their session.
  • The sign-in screen (components/signin/, use-session.ts) sends the username and password to /api/auth/login once, then polls /api/auth/status and relays Duo answers. The page never stores the password.
02

Data only through hooks

Components never call fetch, a UD client or localStorage. Every source lives in services/hooks/use-*.ts and returns a Loadable<T> — { data, loading, error, retry }, rendered by <LoadState>. Each card loads and fails on its own; a slow Stellic profile never holds up the plan.

03

Sources of record, and the writes

  • Every grade, date, requirement, credit and class time comes from Canvas, Stellic or WebReg and is shown as that system states it. Invented data exists only in web/preview/, which src/ never imports.
  • The site writes in exactly two places, each only after the student sees the change and confirms it: submitting their own assignment (services/canvas/canvas-write.ts), and registration — add, drop, swap, edit — from the Schedule page (services/webreg/register.ts, behind the review dialog's explicit confirm). The backend's proxy allows no other write.
  • Registration is real and can't be undone. Exercise it only on the stand-in (section 07). A write's outcome is read from WebReg's own answer; the site never assumes a change happened.
  • The assistant reads, never writes: no chat tool reaches a write. A planned schedule is a draft in the student's browser (use-webreg-plan.ts) until they register it.
  • How the site talks to Stellic and WebReg, and why: Stellic integration, WebReg integration.
04

Folder layout

  • main.tsx injects the styles and renders app.tsx: the session gate, the hash router (services/routes.ts) and the chat conversation, held there so it survives navigation.
  • components/<feature>/ — shell/ (sidebar, top bar, phone nav), signin/, and one folder per page: home/ + dashboard/ (Home), schedule/, grades/ (Courses), deadlines/ + submit/, chat/ (Assistant), degree/, support/ (Help); common/ holds the icon set, the segmented toggle and LoadState.
  • services/ — api/ the two gateways · auth/ the sign-in client · canvas/, stellic/, webreg/ the clients and their mappers · dashboard/ the Canvas–Stellic join · media/ + study/ lectures and study PDFs · tools/ one executor per shared tool name · chat/ the tool loop and context · format/ pure formatting · hooks/ data · types/ view-models · school.ts UD's origins.
  • A new tool is added to @canvas-assistant/shared first; the executor map in services/tools/index.ts is typed by the shared names, so a missing executor fails to compile. Pure logic gets a test in web/tests/.
05

Styling

Plain CSS in src/styles/, one file per area (each under 200 lines), imported as text and joined into one <style> by styles/index.ts; the narrow-screen overrides go last. Every class is prefixed ca-. Colours come from the tokens in tokens.css — never a hex in a component. The palette: paper ground, ink outlines, and one green (--ca-accent, text in --ca-accent-ink) for the action that matters. Poppins for display, Inter for text, loaded by static/index.html.

06

Accessibility and layout

Real <button>, <a href> and <input> + <label>; aria-label on icon-only buttons; touch targets at least 32px; a skip link, and focus moved to the page on each route change; Escape closes panels and dialogs; Enter sends and Shift+Enter adds a line; animations off under prefers-reduced-motion. Every page works at phone width — 16px gutters, no horizontal page scroll (the week calendar scrolls inside its card).

07

Build, serve, stand-in

  • bun run build bundles src/main.tsx into web/dist/ with static/. bun run dev rebuilds on change and serves it on :5175, relaying /api/* to the backend on :3010 (bun run dev:api) — one origin, so the session cookie is first-party and there is no CORS. In production, any server that serves dist/ and relays /api/* over HTTPS does the same.
  • bun run preview runs the whole site against the stand-in UD: it serves web/preview/'s fake Canvas, Media Gallery, Stellic and WebReg on /__standin and starts its own backend on :3011 with UD_STANDIN pointing there. Sign in with any username and password; Duo approves itself, or choose a passcode and enter 123456. Nothing reaches UD.
